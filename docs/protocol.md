# 随手画 · 手机-电视同步协议 v1

本文档是 iOS 端与 Android TV 端实现同步功能的**唯一权威协议定义**。两端各自按此实现，修改协议必须先更新本文档。

## 总览

- 传输：WebSocket（RFC 6455），端点 `ws://<tv-host>:9723/ws`
- 消息格式：UTF-8 JSON 文本帧，每帧一个 JSON 对象
- 坐标：`x`、`y` 均为 `0.0–1.0` 归一化坐标，以 **16:9 画布**左上角为原点；两端各自映射到本地画布尺寸，禁止拉伸或裁切
- 方向：`phone → tv` 表示手机发给电视；`tv → phone` 反之

## 配对流程

本产品**无配对码、无验证**：二维码由电视自身展示，其 URL 即是权威连接目标；连接占用由单设备独占保证（同一时间只有一部手机持有画布），无需额外的码校验。

1. 电视启动后进入配对页（无连接状态），展示二维码，内容为：
   ```
   http://<tv-host>:9723/draw
   ```
   `<tv-host>` 为电视局域网 IPv4 地址（点分十进制）。该 URL 同时是 **Web 画板入口**：浏览器打开即进入网页版画板（见「Web 画板」节）。原生 App 扫码时从 URL 中提取 host（兼容 `suishouhua://<host>:9723` 格式）。
2. 手机建立 WebSocket 连接 `ws://<tv-host>:9723/ws`，随后发送 `hello`。
3. 电视检查占用：
   - 空闲 → 回复 `paired`，进入同步画板
   - 已有设备连接 → 回复 `rejected`（`reason: "in_use"`）并关闭连接

## 消息定义

### phone → tv

| type | 字段 | 说明 |
|---|---|---|
| `hello` | — | 连接后首条消息；电视以是否空闲决定 paired/rejected |
| `stroke_start` | `id: string`, `tool: "pen"\|"marker"`, `color: string`, `width: int` | 落笔。`color` 为 `#RRGGBB`；`width` 为 1/2/3（细/中/粗） |
| `stroke_points` | `id: string`, `points: [[x,y], ...]` | 增量点批量发送，手机端合并间隔 ≤ 16ms |
| `stroke_end` | `id: string` | 收笔，该笔画定型 |
| `erase` | `strokeId: string` | 按笔画擦除（删除整条） |
| `undo` | — | 撤销上一个操作（画/擦/清空均可入栈） |
| `redo` | — | 重做 |
| `clear` | — | 清空画板，入撤销栈 |
| `ping` | — | 心跳（可选），手机每 5s 发送，电视回复 pong 仅作链路探测，**不做超时断开** |

示例：

```json
{"type":"stroke_start","id":"a1b2","tool":"marker","color":"#F28C28","width":2}
{"type":"stroke_points","id":"a1b2","points":[[0.51,0.32],[0.515,0.325]]}
{"type":"stroke_end","id":"a1b2"}
{"type":"undo"}
```

### tv → phone

| type | 字段 | 说明 |
|---|---|---|
| `paired` | `canvasAspect: 1.7777` | 配对成功；随后若电视存有画布内容，先发 `history` |
| `rejected` | `reason: "in_use"` | 已被其他设备占用，随后关闭连接 |
| `history` | `strokes: Stroke[]` | （v1 预留）完整笔画序列。当前单连接模型下断开即丢画布，此消息暂不使用，接收端应静默忽略 |
| `pong` | — | 心跳应答 |

## 语义约定

### 撤销栈
- 操作（新笔画、erase、clear）按时间顺序入栈；`undo` 弹出并撤销最近一个操作，`redo` 恢复。
- 电视端与手机端各自维护相同操作序列，两端通过应用相同消息序列保持一致。
- `history` 中的 `strokes` 即撤销栈回放后的当前可见笔画。

### 断线与释放
- **释放占用的唯一常规途径是电视端手动断开**：遥控器返回键 → 关闭当前连接、清空画布、回配对页。电视端**不做**心跳超时断开、不做空闲检测；手机页面留在后台/闲置时连接持续占用属于预期行为。
- 手机主动关闭页面/杀进程导致的 TCP 断开，电视端按普通断开处理（清屏回配对页）；网络异常形成的半开连接会持续占用，直到有人在电视端手动断开。
- 手机重连（重新扫码）：总是获得全新空白画布（单连接模型下原画布已随断开丢弃）。

### 延迟目标
- 手机落笔 → 电视开始渲染 ≤ 100ms（局域网）。
- `stroke_points` 合并间隔 ≤ 16ms，单帧点数不设上限但建议 ≤ 8。

## Web 画板

电视端同时托管网页版画图客户端（单文件 HTML，内嵌 JS/CSS，无外部资源），路由 `GET /draw`：

- 页面打开后直接发送 `hello` 配对，走完全相同的 WebSocket 协议
- 功能与原生手机端一致：画笔/荧光笔/橡皮擦、5 色 3 档粗细、撤销/重做、清空、导出图片（canvas 下载）
- 触摸/鼠标统一用 pointer events，增量点合并间隔 ≤ 16ms
- 也可在电脑浏览器打开同一 URL 作为联调工具

## 版本

协议版本 v1。未来扩展新消息类型不得破坏已有字段；两端实现应在收到未知 `type` 时**静默忽略**。
