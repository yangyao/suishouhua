# Spec Delta

## Purpose

管理手机与电视之间的连接生命周期：电视展示连接二维码，手机扫码即连（无配对码、无验证），单设备独占，电视端手动断开释放。

## ADDED Requirements

### Requirement: 电视展示连接入口
电视端在未连接状态 SHALL 全屏展示二维码，内容 MUST 为 `http://<tv-host>:9723/draw`（tv-host 为电视局域网地址）。本产品 SHALL NOT 引入配对码或任何验证环节——二维码由电视自身展示，URL 即权威连接目标，占用由单设备独占保证。

#### Scenario: 配对页展示
- **WHEN** 电视应用启动且尚未有手机连接
- **THEN** 屏幕显示标题「手机画，电视看」与二维码，无需任何码或确认

### Requirement: 手机扫码即连
手机端 SHALL 提供相机扫码配对入口，解析二维码中的电视地址并自动建立 WebSocket 连接（发送 `hello`）。电视空闲则回复 `paired`；已被占用则回复 `rejected`（`in_use`）。手机端 MUST 同时提供手动输入电视 IP 的备用入口（无需码）。

#### Scenario: 扫码成功
- **WHEN** 手机相机识别到电视二维码且电视地址可达
- **THEN** 手机发送 hello，收到 paired 后进入绘图画布并显示「已连接电视」

#### Scenario: 扫码但地址不可达
- **WHEN** 二维码解析成功但 3 秒内无法建立连接
- **THEN** 手机显示「无法连接到电视，请确认在同一 Wi-Fi」并保留重试入口

#### Scenario: 手动输入 IP 连接
- **WHEN** 用户输入电视 IP 并提交
- **THEN** 行为与扫码配对一致；电视被占用时显示「电视已被其他手机连接」

### Requirement: 单设备独占连接
电视端在同一时间 MUST 只允许一部手机保持已配对连接。已有手机连接时，新设备的配对请求 SHALL 被拒绝（`in_use`），原连接不受影响。占用的释放途径仅有两种：电视端遥控器返回键手动断开；手机端连接的真实 TCP 断开。

#### Scenario: 第二部手机请求配对
- **WHEN** 电视已连接一部手机，另一部手机发送配对请求
- **THEN** 电视回复 rejected（in_use），新手机显示「电视已被其他手机连接」，原有连接不受影响

### Requirement: 断开与释放
手机端连接的 TCP 真实断开（页面关闭/进程退出）时，电视端 SHALL 清空画布并回到配对页。电视端 MUST NOT 基于心跳超时或空闲时长主动断开连接；手机页面留在后台或闲置时保持占用属于预期行为。

#### Scenario: 手机主动断开
- **WHEN** 已连接的手机退出应用或关闭连接
- **THEN** 电视显示「已断开连接」并回到配对页，画布清空

#### Scenario: 电视端返回键断开
- **WHEN** 已连接状态下用户在电视端按遥控器返回键
- **THEN** 电视关闭连接并回到配对页，新用户可立即扫码

#### Scenario: 手机页面留在后台
- **WHEN** 手机页面进入后台（浏览器节流、锁屏）但 TCP 连接未断
- **THEN** 电视保持已连接状态并持续显示当前画布，不闪切配对页
